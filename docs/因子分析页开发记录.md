# 因子分析页（/factors）开发记录

> 开发日期：2026-03-06
> 对应需求：SRS UC-02（分析因子贡献）、UC-03（配置因子权重）

---

## 1. 开发背景

因子分析页已有基础框架，但存在一个核心缺陷和多个 SRS 需求缺口：

**核心缺陷**：页面展示的 SHAP 值为 `csv_to_sql.py` 用 z-score × 0.04 生成的假数据，与真实模型无关，仅有 10 个硬编码因子。

**SRS 缺口**：
- 雷达图 Hover 无 Top-3 因子明细（UC-02 第 5 步）
- 权重调整后不展示风险指数（UC-03 第 5 步）
- 图表无过渡动画（UC-03 第 6 步要求 800ms cubicOut）
- PUT 响应数据被丢弃，额外发 2 次 GET 请求

## 3. 架构变更

### 3.1 改动前

```
csv_to_sql.py (假SHAP: z-score × 0.04)
    ↓ 写入 MySQL
risk_factor 表 (10 个硬编码因子)
    ↓ FactorServiceImpl 读取
GET /api/risk/radar / GET /api/explain/{date} / PUT /api/config/weights
    ↓
Vue 前端渲染
```

### 3.2 改动后

```
Python Engine (port 5000)
  GET /shap/factors  ←── 新增端点
  └─ engine.get_all_shap_factors()
     ├─ XGBoost TreeExplainer → 全量 SHAP（~25-40 因子）
     ├─ LSTM + XGBoost + Stacking → 真实 riskScore
     └─ 特征名中文映射
        ↓ HTTP JSON（5 分钟内存缓存）
Java Backend (port 8080)
  FactorServiceImpl
  ├─ fetchRealShapFactors() → 优先调 Python
  ├─ CachedShapResult（volatile, 5 分钟 TTL）
  └─ fallback → 数据库（Python 不可用时降级）
        ↓ 原 API 契约不变
Vue 前端
  ├─ PUT 响应直接更新雷达图 + 风险指数
  ├─ 风险指数卡片（riskIndex + riskLevel）
  └─ Tooltip Top-3 因子明细
```

**新增函数：`_auto_name_mapping(raw_col)`**

未命中映射表时的自动提取逻辑，从特征列名中提取中文片段：

```python
def _auto_name_mapping(raw_col: str) -> str:
    if raw_col in FEATURE_NAME_ZH:
        return FEATURE_NAME_ZH[raw_col]
    zh_parts = re.findall(r'[\u4e00-\u9fff]+', raw_col)
    return ''.join(zh_parts) if zh_parts else raw_col
```

### 4.2 Java 后端

#### `src/.../service/impl/FactorServiceImpl.java`

**新增内部类：`CachedShapResult`**

```java
private static class CachedShapResult {
    final String date;
    final double riskScore;
    final List<FactorVO> factors;
    final long timestamp;

    boolean isExpired() {
        return System.currentTimeMillis() - timestamp > 5 * 60 * 1000;
    }
}

private volatile CachedShapResult shapCache;
```

**新增方法：`fetchRealShapFactors()`**

调用 Python Engine `/shap/factors`，解析 JSON 映射到 `FactorVO` 列表，缓存结果。`RestClientException` 时返回 null 触发降级。

**修改方法：`getRadarScores()`、`getExplain()`、`updateWeights()`**

三个公共方法全部改为 Python 优先 + DB 降级策略：

```java
CachedShapResult shap = fetchRealShapFactors();
if (shap != null) {
    // 使用 Python 实时数据
} else {
    // 降级：从数据库读取
}
```

`updateWeights()` 中 `baseRiskIndex` 优先取 Python 真实模型的 `riskScore`。

**新增依赖注入**：`RestTemplate`（constructor 注入）、`@Value("${python.engine.url}")`

#### `src/.../vo/FactorVO.java`

新增字段：

```java
private BigDecimal value;  // 因子实际数值
```

`toFactorVO()` 中补充 `vo.setValue(f.getValue())`。
