# OilRisk 项目配置文档

## 1. 文档目的

这份文档说明当前 `OilRisk_Alert` 项目在本地正常运行时，用户需要准备哪些配置、哪些外部 API、哪些金融数据源可选或必需。

说明基于以下实际代码与配置核对结果，而不是只参考 `README.md`：

- `src/main/resources/application.properties`
- `python_engine/app.py`
- `python_engine/engine.py`
- `python_engine/db.py`
- `python_engine/collector/registry.py`
- `python_engine/collector/scheduler.py`
- `src/main/java/com/example/oilrisk_alert/service/impl/ReportServiceImpl.java`
- `frontend/vite.config.ts`

## 2. 先说结论

### 2.1 如果你只想把项目启动起来并看到页面

你不一定需要提供大模型 API，也不一定需要立刻配置全部金融数据源。

最小可运行条件是：

1. MySQL 8.0 可用。
2. Java 17 可用。
3. Node.js 和 npm 可用，建议 Node 18+。
4. Python 可用，建议 Python 3.10+。
5. 数据库建好并导入 `schema.sql`。
6. Spring Boot 后端能连上 MySQL。
7. Python 推理服务能读取仓库内已有模型文件和历史 CSV。

在这种模式下：

- 页面可以启动。
- 后端接口可以启动。
- Python 推理服务可以启动。
- 基于仓库自带历史数据和模型文件的预测功能可以运行。
- 但 AI 摘要/AI 报告如果没有 LLM API Key，会退回 Mock 文本。
- 实时因子采集和自动回填如果缺少数据源配置，会部分失败或全部失败。

### 2.2 如果你想“完整功能正常运行”

完整功能包括：

- 实时因子采集
- 定时调度
- 缺口回填
- 数据落库
- 风险指数刷新
- AI 风险摘要
- AI 预警报告

则用户需要准备：

1. MySQL 账号密码
2. FRED API Key
3. EIA API Key
4. 可访问 Yahoo Finance / FRED / EIA / GDELT 的网络环境
5. 一个兼容 OpenAI Chat Completions 风格接口的大模型 API

## 3. 项目运行结构

当前项目是三段式架构：

- 前端：Vue 3 + Vite，默认端口 `5173`
- 后端：Spring Boot，默认端口 `8080`
- 推理引擎：FastAPI，默认端口 `5000`
- 数据库：MySQL，默认端口 `3306`

端口关系：

- 前端通过 `/api` 代理到 `http://localhost:8080`
- Spring Boot 通过 `python.engine.url=http://localhost:5000` 调用 Python 推理引擎

环境版本判断依据：

- Java 17：来自 `pom.xml`
- Python 3.10+：基于代码中 `OilRiskEngine | None` 这类联合类型语法推断
- Node 18+：这是对 Vite 6 的稳妥建议，不是代码里强制写死的版本

## 4. 用户必须提供的配置

## 4.1 数据库配置

这是强依赖，没有数据库，Spring Boot 无法正常运行，Python 的实时采集结果也无法持久化。

配置位置：

- `src/main/resources/application.properties`
- `python_engine/.env` 或系统环境变量

你至少要提供：

- `spring.datasource.username`
- `spring.datasource.password`
- `DB_HOST`
- `DB_PORT`
- `DB_NAME`
- `DB_USER`
- `DB_PASSWORD`

建议统一使用同一套 MySQL 连接信息，避免 Java 和 Python 连到不同数据库。

建库命令：

```sql
CREATE DATABASE oilrisk CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;
```

建表命令：

```bash
mysql -u root -p oilrisk < src/main/resources/schema.sql
```

## 4.2 大模型 API 配置

这是可选依赖，不影响系统启动，但会影响 AI 能力。

配置位置：

- `src/main/resources/application.properties`

对应字段：

```properties
llm.api.key=
llm.api.url=https://apis.iflow.cn/v1/chat/completions
llm.api.model=qwen3-max
```

实际行为：

- 没有 `llm.api.key` 时，`AI Summary` 和 `AI Report` 不会报错退出。
- 系统会自动退回 mock 文本生成逻辑。
- 也就是说，LLM 不是“启动硬依赖”，但它是“完整功能依赖”。

对 API 的要求：

- 接口形态需要兼容 OpenAI `chat/completions`
- 支持 Bearer Token
- 支持流式返回 SSE

如果你用的是其他厂商模型，只要满足以上接口风格即可，不一定非要用 `iflow` 或 `qwen3-max`。

## 4.3 金融数据源配置

这部分要分清楚：不是所有数据源都需要用户自己申请 Key。

### 必须由用户提供 Key 的数据源

1. FRED
   - 用途：美债收益率、通胀预期、高收益利差、汇率、消费者信心等宏观/金融因子
   - 配置项：`FRED_API_KEY`
   - 代码位置：`python_engine/collector/fred_collector.py`

2. EIA
   - 用途：库欣库存、美国产量、炼厂开工率等能源供给因子
   - 配置项：`EIA_API_KEY`
   - 代码位置：`python_engine/collector/eia_collector.py`

### 不需要用户提供 Key，但需要网络可访问的数据源

1. Yahoo Finance
   - 用途：WTI、Brent、RBOB、天然气、VIX、OVX、SP500、美元指数、黄金等日频市场因子
   - 采集方式：`yfinance`
   - 是否需要 API Key：不需要

2. GDELT
   - 用途：新闻情绪、地缘政治事件强度、GPR 近似指标
   - 是否需要 API Key：不需要

### 代码中实际依赖的数据源分布

- `yfinance`: 20 个因子
- `FRED`: 7 个因子
- `EIA`: 5 个因子
- `GDELT`: 6 个因子

### 哪些是“必须有”的

要区分两种目标：

1. 只启动项目并使用仓库自带历史数据做预测
   - 不强制要求用户立刻配置 FRED / EIA / GDELT / Yahoo Finance
   - 因为仓库已经自带：
     - `OilRisk_System/*.pkl`
     - `OilRisk_System/best_lstm.pt`
     - `data/Final_Oil_Dataset_Cleaned.csv`

2. 使用实时采集、定时更新、回填、最新风险计算
   - FRED API Key：必需
   - EIA API Key：必需
   - Yahoo Finance 网络访问：必需
   - GDELT 网络访问：建议提供，否则地缘和新闻情绪因子会缺失

## 4.4 网络代理配置

这项不是代码逻辑强依赖，但在中国大陆网络环境下通常是事实上的必需项。

配置位置：

- `python_engine/.env`

配置项：

```env
HTTP_PROXY=http://127.0.0.1:7890
HTTPS_PROXY=http://127.0.0.1:7890
```

原因：

- `FRED`
- `EIA`
- `GDELT`

这些外部服务在中国大陆网络环境下容易出现 SSL EOF、连接超时或请求失败。

## 5. 推荐的配置文件模板

## 5.1 Spring Boot 配置模板

文件：`src/main/resources/application.properties`

```properties
spring.application.name=OilRisk_Alert
server.port=8080

spring.datasource.url=jdbc:mysql://localhost:3306/oilrisk?useSSL=false&allowPublicKeyRetrieval=true&serverTimezone=Asia/Shanghai&characterEncoding=UTF-8
spring.datasource.driver-class-name=com.mysql.cj.jdbc.Driver
spring.datasource.username=你的MySQL用户名
spring.datasource.password=你的MySQL密码
spring.sql.init.mode=never
spring.sql.init.encoding=UTF-8

mybatis.mapper-locations=classpath:mapper/*.xml
mybatis.type-aliases-package=com.example.oilrisk_alert.entity
mybatis.configuration.map-underscore-to-camel-case=true

spring.jackson.date-format=yyyy-MM-dd
spring.jackson.time-zone=Asia/Shanghai

python.engine.url=http://localhost:5000

llm.api.key=你的大模型APIKey
llm.api.url=你的聊天补全接口地址
llm.api.model=你的模型名
```

## 5.2 Python `.env` 模板

文件：`python_engine/.env`

如果该文件不存在，请手动创建。

```env
DB_HOST=localhost
DB_PORT=3306
DB_NAME=oilrisk
DB_USER=你的MySQL用户名
DB_PASSWORD=你的MySQL密码

FRED_API_KEY=你的FRED_API_KEY
EIA_API_KEY=你的EIA_API_KEY

HTTP_PROXY=http://127.0.0.1:7890
HTTPS_PROXY=http://127.0.0.1:7890

YF_BATCH_SIZE=5
YF_BATCH_DELAY=2.0
YF_SINGLE_DELAY=1.5

BACKFILL_ON_STARTUP=false
COLLECT_ON_STARTUP=false
```

## 6. 启动顺序

建议按下面顺序启动：

### 6.1 启动 Python 推理引擎

```bash
cd python_engine
pip install -r requirements.txt
uvicorn app:app --host 0.0.0.0 --port 5000
```

### 6.2 启动 Spring Boot 后端

```bash
mvn spring-boot:run
```

或直接在 IDE 运行：

- `src/main/java/com/example/oilrisk_alert/OilRiskAlertApplication.java`

### 6.3 启动前端

```bash
cd frontend
npm install
npm run dev
```

访问地址：

- `http://localhost:5173`

## 7. 运行模式判断

## 7.1 最小可运行模式

用户至少需要提供：

- MySQL 连接信息

可不提供：

- `llm.api.key`
- `FRED_API_KEY`
- `EIA_API_KEY`

这时能做的事情：

- 启动前后端和 Python 服务
- 加载已有模型
- 使用历史 CSV 做基础预测
- 查看页面

这时会缺失的能力：

- AI 真正生成内容
- 实时采集
- 自动回填
- 完整实时风险更新

## 7.2 完整运行模式

用户需要全部提供：

- MySQL 连接信息
- `FRED_API_KEY`
- `EIA_API_KEY`
- 可用代理或外网访问能力
- LLM API 的 `key + url + model`

这时能使用完整链路：

- 定时采集
- 手动采集
- 自动回填
- 风险分数持久化
- 预警记录生成
- AI 风险摘要
- AI 预警报告

## 8. 当前仓库存在的配置风险

这个部分不是推测，是我从当前文件中直接读到的事实。

### 8.1 存在明文密钥

以下文件当前含有明文敏感信息：

- `src/main/resources/application.properties`
- `python_engine/.env`

影响：

- 如果仓库被提交、分享或上传，数据库密码和 API Key 可能泄露。

建议：

1. 立即轮换已暴露的 LLM / FRED / EIA 密钥。
2. 将真实密钥改为本地环境变量或未提交的私有配置文件。
3. 提交仓库时只保留示例配置。

### 8.2 README 不能完全当作唯一依据

当前 `README.md` 含有未解决的 Git 冲突标记：

- `<<<<<<< HEAD`
- `=======`
- `>>>>>>>`

影响：

- 说明文档本身不完全可信。
- 配置应以代码实际实现为准。

如果你要让这个项目完整跑起来，最终需要准备的是这份清单：

3. EIA API Key

LLM API 和金融数据源可以后补。
