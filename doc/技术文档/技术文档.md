## 一、系统概述

### 1.1 项目定位

OilRisk-Alert 是一个面向原油市场的风险预警系统，核心能力为：基于多模型集成（LSTM + XGBoost + Stacking）预测未来 5 个交易日的 WTI 原油价格风险，并通过 Web 仪表盘实现风险可视化、因子归因分析、预警管理与模型回测。系统支持实时因子采集，可从静态 CSV 数据无缝升级为每日自动更新的实时风险监测。

### 1.2 系统边界

| 范围 | 说明 |
|------|------|
| **包含** | 风险仪表盘、因子分析、预警引擎、AI 报告、模型回测、实时因子采集 |
| **不包含** | 用户鉴权、模型自动再训练、多租户 |
| **部署形态** | 本地单机（演示用途） |
| **数据范围** | 2015 年至今，默认展示近两年 |

## 四、ML 模型体系

### 4.1 Stacking 集成架构

系统采用两层 Stacking 集成学习架构：第 1 层两个异构基模型分别捕捉趋势信号和冲击信号，第 2 层 Ridge 元学习器融合两者的输出与市场状态，给出最终风险预测。

```
CSV 原始数据 (400+ 列)
    │
    ├──▶ 第1层 · LSTM 趋势专家
    │     特征: 27维 × 30日窗口
    │     输出: pred_price, up_prob  →  隐含收益率 lstm_impl_return
    │
    ├──▶ 第1层 · XGBoost 冲击专家
    │     特征: ~50 个冲击相关列
    │     输出: risk = max(0, -next_return)  →  xgb_risk
    │
    └──▶ 第2层 · Ridge 元学习器
          输入: 7 市场状态 + lstm_impl_return + xgb_risk = 9 维
          输出: pred_return_pct (%)  →  风险评分 0-100
```

### 4.2 LSTM 趋势专家

**任务**：预测 5 个交易日后 WTI 收盘价与涨跌方向。

**特征工程 (27 维)**：

| 类别 | 特征 | 数量 |
|------|------|------|
| 价格 | WTI 收盘价 | 1 |
| 日频金融 | CRB、SP500、TIPS、HY Spread、VIX、OVX、库欣库存 | 7 |
| 月频变化量 | OPEC/沙特/俄罗斯产量、中国/欧盟 PMI、美国消费者信心（月度差分） | 6 |
| 均线技术 | MA5/20/60 及偏离率 | 6 |
| 动量波动 | 5/20 日对数动量、20 日历史波动率、库欣库存 5 日变化 | 4 |
| 方向性 | 动量加速度、VIX/OVX 3 日变化率 | 3 |

**网络结构**：

```
Input (batch, 30, 27)
  → LSTM(128, return_sequences=True) → BatchNorm
  → LSTM(64)  → BatchNorm → Dropout(0.2)
  ├── 价格头: Linear(64→32, ReLU) → Linear(32→1)         输出: 预测价格
  └── 分类头: Linear(64→16, ReLU) → Linear(16→1, Sigmoid) 输出: 上涨概率
```

**关键配置**：

| 参数 | 值 | 说明 |
|------|-----|------|
| Lookback | 30 天 | 输入序列长度 |
| Horizon | 5 天 | 预测时间跨度 |
| Loss | Huber + 0.5 × BCE | 联合损失，cls_weight=0.5 是实验验证的平衡点 |
| 优化器 | Adam, lr=5e-4 | 配合 ReduceLROnPlateau |
| 早停 | patience=30 | 基于 val_loss |
| 缩放器 | RobustScaler | 特征和价格分别缩放 |
| 数据切分 | 70/15/15 | 严格按时间序列，不 shuffle |

### 4.3 XGBoost 冲击专家

**任务**：预测下一个交易日的下跌风险强度 `risk = max(0, -next_return)`。

**特征选择**：从全部数值列中，按关键词 `ovx, vix, hy, spread, credit, risk, sentiment, news, gpr, diff, delta, change, return, vol` 等自动筛选约 50 列冲击相关特征。

**超参数**：`n_estimators=600, max_depth=4, lr=0.03, subsample=0.8, colsample_bytree=0.8, reg_lambda=1.0, min_child_weight=5`

**评估**：TimeSeriesSplit 5 折，Spearman 相关系数 + Top10% 冲击命中率/Lift。

### 4.4 Ridge 元学习器

**输入 (9 维)**：

| 维度 | 来源 |
|------|------|
| VIX、OVX、美债 10Y 收益率、美元指数、新闻情感、地缘评分、标普 500 | 原始市场状态 |
| `lstm_impl_return` | (LSTM 预测价格 - 当前价格) / 当前价格 |
| `xgb_risk` | XGBoost 下跌风险得分 |

**训练**：StandardScaler 标准化 → Alpha 网格搜索 `[1e-4, ..., 100]` → 验证集 MAE 选优 → 训练+验证合并重训。

### 4.5 风险评分映射

```
risk_score = clamp(50 - pred_return_pct × 4, 3, 97)
```

- pred_return_pct > 0（看涨）→ score < 50 → 低风险
- pred_return_pct < 0（看跌）→ score > 50 → 高风险

**风险等级**：Low [0, 40) / Medium [40, 70) / High [70, 100]

## 五、Python 推理引擎

### 5.1 核心类：`OilRiskEngine`

位于 `python_engine/engine.py`，启动时加载全部模型文件和 CSV 数据到内存。

**初始化流程**：

```
__init__()
```

### 5.3 SHAP 因子归因

系统使用 `shap.TreeExplainer` 对 XGBoost 模型计算 SHAP 值，量化每个特征对预测结果的边际贡献。

- 全量 SHAP 值计算后按 `|shap_value|` 降序排列
- 每个因子自动分类为 5 个类别：`SUPPLY_DEMAND / MACRO / FINANCIAL / GEOPOLITICAL / SENTIMENT`
- 因子中文名通过 `FEATURE_NAME_ZH` 映射表或正则自动提取

## 六、实时因子采集系统

### 6.1 架构

```
APScheduler (AsyncIO)
    │
    ├── 每日 06:00 ── 日频采集 (yfinance + FRED)
    ├── 每周四 06:00 ── 周频采集 (EIA)
    ├── 每月 2 日 06:00 ── 月频采集 (OPEC/PMI)
    └── 每日 12:00 ── GDELT 地缘/情绪采集
            │
            ▼
    FactorCollector (base.py)
    ├── yfinance_collector.py   WTI/Brent/VIX/OVX/SP500/美元指数/CRB/黄金等
    ├── fred_collector.py       美债收益率/通胀预期/高收益利差/联邦基金利率等
    ├── eia_collector.py        库欣库存/商业原油库存/汽油库存/炼厂开工率/产量
    └── gdelt_collector.py      地缘政治评分/新闻情感指数
            │
            ▼
    registry.py (因子注册表)
    ├── factor_key → collector + ticker/series_id + column_name
    └── ~60 个因子，分 P0-P3 四个优先级
            │
            ▼
    db.py → factor_realtime 表 + collection_log 表
            │
            ▼
    engine.reload_from_db() → 合并最新数据 → 三模型推理
```

### 6.2 因子优先级

| 级别 | 说明 | 数量 | 数据源 |
|------|------|------|--------|
| **P0** | 三模型共用的核心因子 | ~8 | yfinance + FRED |
| **P1** | XGBoost/Stacking 使用 | ~9 | yfinance + FRED |
| **P2** | 周/月频因子 | ~10 | EIA + FRED + akshare |
| **P3** | 地缘/情绪替代因子 | ~12 | GDELT |

### 6.3 采集器基类

```python
class FactorCollector(ABC):
    MAX_RETRIES = 3
    RETRY_DELAY = 5  # 秒，指数递增

    @abstractmethod
    def collect(self, date: str) -> dict[str, float | None]: ...

    def collect_with_retry(self, date: str) -> dict[str, float | None]:
        # 3 次重试，逐次递增延迟，全部失败返回 {key: None}
```

### 6.4 数据合并策略

```
历史 CSV (2015 ~ 截止日)  +  factor_realtime 表 (截止日之后)
                   │
                   ▼  pd.concat → 按日期去重(keep=last) → sort_index → ffill/bfill
                   │
           self.df_raw (内存 DataFrame)
                   │
                   ▼  _build_lstm_features() 重算技术指标
                   │
           self.df_feat (LSTM 27 维特征)
                   │
                   ▼  三模型推理 → 风险评分
```

**关键约束**：

- 月频因子在日频 DataFrame 中通过 ffill 处理，与训练时一致
- 新数据追加后必须重算 MA/动量等技术指标（依赖窗口数据）
- DB 连接失败时自动回退 CSV 模式，保证服务不中断

### 7.4 核心业务逻辑

**因子评分（雷达图）**：按 5 个类别分组因子 → 各类别平均 |SHAP| → 乘类别权重 → 归一化 0-100。

**权重调节**：用户拖动滑块 → debounce 300ms → PUT 新权重 → 重算 `adjustedIndex = originalIndex × (加权SHAP / 无权SHAP)` → 前端动画过渡更新。

**AI 报告**：检查缓存 → 有则直接 SSE 返回 → 无则组装 Prompt（预警数据 + 因子上下文）→ 调用 LLM streaming → 逐 token SSE 推送 → 生成完毕写入缓存。

**LTTB 降采样**：时序数据超过 2000 点时，后端自动应用 Largest-Triangle-Three-Buckets 算法降采样，保留视觉特征。

## 十一、关键技术决策

| 决策 | 说明 |
|------|------|
| **Stacking 而非单模型** | LSTM 擅长趋势，XGBoost 擅长极端冲击，Ridge 融合两者 + 市场状态 |
| **SHAP 而非 Gain** | SHAP 提供方向性归因（正/负贡献），Gain 仅衡量特征使用频率 |
| **RobustScaler** | 金融数据含异常值（如油价负值事件），RobustScaler 比 StandardScaler 更稳健 |
| **时序严格切分** | 70/15/15 按时间顺序，不 shuffle，防止未来信息泄漏 |
| **XGBoost 不前向填充** | 保持与训练时一致，仅元学习器的市场状态特征做 ffill |
| **cls_weight=0.5** | LSTM 分类权重经过 [0.1, 0.5, 1.0] 实验，0.5 是价格回归与方向分类的平衡点 |
| **双头独立隐层** | LSTM 价格头和分类头各自有独立 FC 层，避免争抢共享表示 |
| **LTTB 降采样** | >2000 点时自动降采样，保留视觉特征同时避免前端卡顿 |
| **AI 报告缓存** | LLM 生成后存入 `alert.ai_report` 字段，避免重复调用 |
| **LLM 可选** | 无 API Key 时回退 Mock 模板，不影响核心功能 |
| **DB 降级** | Python 引擎 DB 连接失败时自动回退 CSV 模式 |
| **schema.sql IF NOT EXISTS** | 避免重启时 DROP 表导致数据丢失 |

## 十二、数据校验与容错

### 12.1 采集校验

| 校验项 | 规则 | 处理 |
|--------|------|------|
| 非空检查 | P0 因子不可为空 | 重试 3 次 → 失败沿用前一日值 |
| 合理范围 | WTI ∈ [10, 200]，VIX ∈ [5, 90] | 超范围不入库，记告警 |
| 日偏差 | 与前日变化 > 20% | 入库但标记"待核查" |
| 交易日判断 | 跳过周末和美国公休 | pandas_market_calendars |

### 12.2 推理容错

| 场景 | 处理 |
|------|------|
| 部分因子缺失 | P0 沿用前日 + 标记；P2/P3 ffill 填充 |
| 全部采集失败 | 不推理，保留上次结果 |
| 推理异常 | 捕获回退，记错误日志 |
| DB 连接失败 | 回退 CSV 模式 |
| LLM 不可用 | 返回 Mock 模板 |

### 12.3 安全防护

- SQL 注入：后端对 sort/order/level 参数做白名单校验
- 参数校验：Pydantic (Python) + Spring Validation (Java)
- API Key 脱敏：LLM 配置 GET 接口对 Key 做掩码处理
