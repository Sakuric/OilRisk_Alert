# 实时因子获取需求开发文档

> **版本**：v1.0
> **日期**：2026-03-09
> **需求概述**：定时采集油价相关因子数据，存入数据库，驱动模型实时推理，结果自动反映在前端仪表盘上。

---

## 一、需求背景

当前系统的模型推理基于静态 CSV 文件（`Final_Oil_Dataset_Cleaned.csv`），数据截止到历史某一天。系统每次重启只能展示固定的风险评分，无法反映市场最新动态。

本需求要补齐 ETL Pipeline，实现：
1. **定时采集**：每个交易日自动从公开 API 获取最新因子数据
2. **持久化存储**：采集数据写入 MySQL，支持历史追溯
3. **自动推理**：采集完成后触发模型重新推理，更新风险评分
4. **仪表盘刷新**：前端感知数据更新，展示最新风险状态

### 5.2 采集器基类

```python
class FactorCollector(ABC):
    """采集器基类，提供重试、超时、日志标准化。"""

    MAX_RETRIES = 3
    RETRY_DELAY = 5  # 秒

    @abstractmethod
    def collect(self, date: str) -> dict[str, float | None]:
        """
        采集指定日期的因子数据。
        返回: {factor_key: value} 字典，失败的 key 值为 None。
        """
        ...

    def collect_with_retry(self, date: str) -> dict[str, float | None]:
        """带重试的采集入口。"""
        for attempt in range(self.MAX_RETRIES):
            try:
                return self.collect(date)
            except Exception as e:
                if attempt == self.MAX_RETRIES - 1:
                    logger.error(f"[{self.__class__.__name__}] 采集失败: {e}")
                    return {k: None for k in self.factor_keys}
                time.sleep(self.RETRY_DELAY * (attempt + 1))
```

## 六、推理引擎改造

### 6.1 `engine.py` 新增方法

```python
class OilRiskEngine:

    def reload_from_db(self, db_conn) -> dict:
        """
        从 MySQL 读取最新因子数据，合并到历史 DataFrame，重新推理。

        流程:
        1. 查询 factor_realtime 表，获取所有最新因子值
        2. 将 factor_key 映射回 CSV 列名
        3. 构造新行 append 到 self.df_raw
        4. 重算 LSTM 特征 (技术指标)
        5. 执行三模型推理
        6. 返回推理结果
        """
        # 从 DB 读取最新日期的全部因子
        latest_factors = db.get_latest_factors(db_conn)
        if not latest_factors:
            return {"error": "No factor data available"}

        # 构造新行（列名对齐 CSV）
        new_row = {}
        for factor_key, value in latest_factors.items():
            col_name = FACTOR_REGISTRY[factor_key]["column_name"]
            new_row[col_name] = value

        new_date = max(r["date"] for r in latest_factors.values())
        new_df = pd.DataFrame([new_row], index=pd.DatetimeIndex([new_date]))

        # 合并到现有数据
        self.df_raw = pd.concat([self.df_raw, new_df])
        self.df_raw = self.df_raw[~self.df_raw.index.duplicated(keep="last")]
        self.df_raw = self.df_raw.sort_index()
        self.df_raw = self.df_raw.ffill().bfill()

        # 重建 LSTM 特征
        wti_valid = self.df_raw[self.df_raw[TARGET_COL].notna()].index
        df_valid = self.df_raw.loc[wti_valid]
        self.df_feat = _build_lstm_features(df_valid)

        # 清除 SHAP 缓存
        self._shap_cache = None

        # 重新推理
        return self.predict_daily()
```

### 6.2 数据合并策略

```
历史 CSV 数据 (2015 ~ 数据截止日)
        │
        ▼
┌───────────────────┐     ┌─────────────────────┐
│   self.df_raw     │ ◄── │  factor_realtime 表  │
│  (内存 DataFrame) │     │  (最新采集数据)      │
└───────────────────┘     └─────────────────────┘
        │
        │  ffill: 月频数据用最近值向前填充
        │  bfill: 起始段缺失用最近已知值回填
        ▼
┌───────────────────┐
│  _build_lstm_features()  → self.df_feat
└───────────────────┘
        │
        ▼
   三模型推理 → 风险评分
```

**关键约束**：
- 月频因子（PMI、OPEC 产量等）在日频 DataFrame 中通过前向填充(ffill)处理，与训练时一致
- 新数据追加后必须重新计算技术指标（MA、动量等），因为这些指标依赖窗口数据
- 合并时按日期去重（保留最新值），避免重复行

- 数据日期 = 当前交易日 → 绿色"实时"标签
- 数据日期 > 1 个交易日 → 黄色"滞后"标签 + 提示
- 采集失败 → 红色"异常"标签

### 8.2 自动刷新机制

方案：**轮询**（简单可靠，适合演示场景）

```typescript
// composables/useDataFreshness.ts
const POLL_INTERVAL = 60_000 // 60 秒

export function useDataFreshness() {
    const systemStatus = ref<SystemStatus | null>(null)

    const { data, execute } = useAsyncData(
        () => api.get('/api/system/status'),
        { immediate: true }
    )

    // 每 60 秒轮询一次
    const timer = setInterval(execute, POLL_INTERVAL)
    onUnmounted(() => clearInterval(timer))

    // 如果发现数据日期变化，触发 risk store 刷新
    watch(() => data.value?.dataDate, (newDate, oldDate) => {
        if (newDate && newDate !== oldDate) {
            riskStore.fetchCurrentRisk()
            riskStore.fetchTimeseries()
        }
    })

    return { systemStatus }
}
```

## 九、数据校验与容错

### 9.1 采集阶段校验

| 校验项 | 规则 | 处理方式 |
|--------|------|---------|
| 非空检查 | 核心因子（P0）不可为空 | 重试 → 失败则标记，沿用前一日值 |
| 合理范围 | WTI ∈ [10, 200]，VIX ∈ [5, 90] 等 | 超范围则记日志告警，不入库 |
| 日偏差 | 与前一交易日相比变化 > 20% | 记告警但仍入库，标记为"待核查" |
| 交易日判断 | 跳过非交易日（周末、美国公休） | 使用 `pandas_market_calendars` 判断 |

### 9.2 推理阶段容错

| 场景 | 处理方式 |
|------|---------|
| 部分因子缺失 | P0 因子缺失 → 沿用前一日值 + 标记"数据不完整"；P2/P3 缺失 → ffill 填充 |
| 全部采集失败 | 不触发推理，保留上次结果，前端标记"数据非实时" |
| 推理过程异常 | 捕获异常，回退到上次结果，记录错误日志 |
| DB 连接失败 | 退回 CSV 模式（现有逻辑），保证服务不中断 |

### 9.3 GDELT 替代因子质量说明

GDELT 生成的地缘/情绪因子是**近似值**，与原始训练数据中的人工标注可能存在偏差：
- 地缘评分：GDELT GoldsteinScale 范围 [-10, 10]，需线性映射到原始数据的 [0, 10] 范围
- 新闻情绪：GDELT AvgTone 需校准到原始 News_Sentiment 的分布区间
- 建议对 GDELT 因子设置更保守的权重或做分布校准

## 十三、风险与约束

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| yfinance 被限流或接口变更 | 日频核心因子采集中断 | 保留 CSV 兜底；yfinance 更新频繁可 pin 版本 |
| FRED/EIA API Key 配额 | 免费 Key 有请求频率限制 | 单次批量请求；错峰调度；缓存已获取数据 |
| GDELT 地缘评分与原始训练数据分布不同 | 模型对地缘因子的预测偏差 | 做分布校准(z-score align)；或降低该类因子权重 |
| 非交易日数据缺失 | 周末/假期无新数据 | 交易日历判断，非交易日不触发采集 |
| 数据源延迟 | 部分因子更新滞后（如 EIA 库存偶尔延迟发布） | 重试机制 + 允许 T+1 容差 |
| MySQL 与 CSV 数据不一致 | 推理结果出现跳变 | 首次上线时做历史数据回填，对齐 CSV 与 DB |
